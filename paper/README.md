# LinkedIn short-paper handoff

The user will write the LinkedIn report in a separate chat. No LinkedIn manuscript has been generated by this preparation task.

The old Airbnb manuscript, bibliography and NeurIPS 2025 style are archived under `archive/airbnb/paper/`. Do not submit them as the LinkedIn report.

Use [the submission checklist](../docs/SUBMISSION_REQUIREMENTS.md), [dataset card](../docs/LINKEDIN_DATASET_CARD.md) and [source/integration audit](../docs/MULTABENCH_COMPLIANCE_AUDIT.md). The handout links the [NeurIPS 2026 template](https://www.overleaf.com/latex/templates/formatting-instructions-for-neurips-2026/bjdwqfdkyftc).

The paper must be in English, at most four main-text pages, with references excluded from that limit. Appendices are restricted to result tables/metrics. Include title/abstract, introduction, related work, dataset/method, results, and conclusion with limitations and future work.

Use the final six-fold physical-batch-256 LinkedIn results once available. As of 2026-10-25, the latest local backup has 95/120 successful evaluations and only folds 0-3 are complete. Do not mix in the completed 16x16 experiment or describe provisional four-fold means as final.

Native dataset-registration/loading integration is now provided separately; see [native instructions](../docs/NATIVE_MULTABENCH.md). It preserves the official evaluation/model/training files and passed exact data/split parity plus a real structured LightGBM CLI check. The historical VM-v1 run still used the original external runner and zero data-loader workers rather than the upstream default of four. Report that provenance accurately; do not relabel existing results as a new native CLI run.
